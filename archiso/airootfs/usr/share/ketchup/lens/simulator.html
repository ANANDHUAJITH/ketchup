KetchupVM — a computer you can single-step

CPU → MMU/TLB → L1 cache → RAM frames → disk, plus a tiny kernel: page-fault handler, system calls, scheduler, page cache. Sizes are tiny on purpose so you can see everything.
How to read this machine (click)
Address space: each process has 256 bytes of virtual memory = 16 pages × 16 bytes. RAM has only a few 16-byte frames, so most pages live on disk until touched.
One memory access: the CPU asks the TLB (a tiny cache of translations). Miss → it walks the page table in RAM. If the page is not present → page fault: the kernel picks a frame (evicting one if RAM is full), reads the page from disk (~2000 cycles!), updates the page table, retries. Then the physical address goes through the L1 cache (4 lines × 4 bytes, direct-mapped): hit = 1 cycle, miss = fetch from RAM (30 cycles).
Kernel: SYSCALL switches USER→KERNEL mode. A timer interrupt ends a process's time slice and the scheduler switches to the next one (saving/restoring registers).
Instructions: MOV ADD SUB MUL AND OR XOR SHL SHR CMP · JMP JE JNE JL JGE JG JLE · LOAD Rd,[Rs+off] · STORE [Rs+off],Rs|imm · PUSH POP CALL RET · SYSCALL (R0 = number: 1 write(R1=ptr,R2=len), 2 exit, 3 yield, 4 read_file(R1=block,R2=dest), 5 getpid, 6 sleep(R1)) · directives .data ADDR b1 b2… .string ADDR "text" .equ NAME value. Registers are 16-bit; memory is bytes. Instruction fetch is not modelled (code is not stored in RAM).
